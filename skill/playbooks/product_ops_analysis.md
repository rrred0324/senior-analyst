# 产品运营 Playbook

适用任务：PMF 诊断、增长分析、留存分析、激活优化、B2B SaaS 分析

## 核心流程

### 产品诊断五步法

```
Step 1: 生命周期阶段识别
    ├─ 探索期（验证 PMF）
    ├─ 成长期（用户爆发）
    ├─ 成熟期（存量经营）
    └─ 衰退期（转型）

Step 2: PMF 状态判断
    ├─ 强信号：自发推荐、自然留存、付费意愿
    ├─ 弱信号：营销驱动、留存不稳
    └─ 伪信号：补贴驱动、下载高但留存低

Step 3: 增长引擎识别
    ├─ PLG（产品驱动）
    ├─ SLG（销售驱动）
    ├─ MLG（营销驱动）
    └─ 混合模式

Step 4: 单位经济健康度
    ├─ LTV/CAC
    ├─ 回本周期
    ├─ Cohort P&L

Step 5: 留存质量分析
    ├─ 留存曲线形状
    ├─ Aha 时刻识别
    ├─ 流失归因
    └─ 增长会计
```

## PMF 判断标准

### 强信号（L1/L2 证据）
- 用户自发推荐（非诱导）
- 自然留存显著高于基准
- 用户主动付费/续费
- NPS 显著为正

### 伪信号（警惕）
- ⚠️ 增长靠补贴驱动
- ⚠️ 下载量高但留存低
- ⚠️ 用户说喜欢但行为不复用
- ⚠️ 口碑传播弱
- ⚠️ 收入依赖单一渠道

### PMF 强度评分
| 维度 | 权重 | 评分标准 |
|------|------|---------|
| 自然留存 | 30% | 取消补贴后 30 日留存 |
| NPS | 20% | 净推荐值 |
| 付费意愿 | 20% | 付费转化率 |
| 自发传播 | 15% | K 因子 |
| 使用深度 | 15% | 核心功能使用率 |

## 增长分析框架

### AARRR 漏斗（用户视角）
```
Acquisition → Activation → Retention → Revenue → Referral
```

**注意**：AARRR 是漏斗模型，**不是**产品阶段框架。

### 增长会计（月度追踪）
```
本期 MAU = 上期 MAU + New + Resurrected - Churned
```

诊断四象限：
| 情景 | New | Retained | Churned | 诊断 |
|------|-----|----------|---------|------|
| A | 高 | 低 | 高 | 靠拉新补漏，留存有问题 |
| B | 中 | 高 | 低 | 健康增长 |
| C | 低 | 高 | 低 | 成熟期，缺乏新增 |
| D | 低 | 低 | 高 | 衰退，需转型 |

## B2B SaaS 专用指标

| 指标 | 健康标准 |
|------|---------|
| NDR | >110% 优秀，>120% 顶级 |
| GDR | >90% 健康 |
| Logo Churn | <5% 年化 |
| CAC Payback | <12 个月 |
| Magic Number | >1 健康 |
| Rule of 40 | 增长率 + 利润率 ≥ 40% |

## 激活与 Onboarding

### Aha 时刻识别
```
Step 1: 对比留存用户 vs 流失用户的行为差异
Step 2: 找到留存用户在前 N 天的差异化动作
Step 3: 量化该动作与留存的相关性
Step 4: A/B 测试验证因果
Step 5: 设计 Onboarding 引导用户达到
```

### 经典 Aha 时刻
- Facebook：7 天加 10 个好友
- Twitter：关注 30 个人
- Slack：团队发送 2000 条消息

## 常见陷阱

| 陷阱 | 表现 | 应对 |
|------|------|------|
| 把 AARRR 当阶段 | "我们在 Retention 阶段" | 按生命周期分阶段 |
| 伪 PMF 判断 | 补贴下的留存 | 取消补贴测试 |
| 混用新老客 | LTV 被平均 | Cohort 分析 |
| 只看结果指标 | 忽略过程 | 三指标同看 |
| 忽视护栏指标 | 为增长损害体验 | 加入满意度、投诉 |
