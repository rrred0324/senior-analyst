# 规则约束

本文档定义 skill 在执行分析时必须遵守的硬性规则。

## 一、证据规则

### 1.1 三类表达必须分离
所有判断必须明确归类：
- 【事实】：有数据/文件直接支撑
- 【经验】：行业共识/经典理论/阈值
- 【推断】：基于假设的推理

**错误示例**：
> "这家公司利润率低，说明商业模式有问题。"

**正确示例**：
> 【事实】公司毛利率 12%，同行业平均 25%。
> 【经验】制造业毛利率 <15% 通常意味着缺乏定价权。
> 【推断】公司可能处于同质化竞争或规模不足阶段，需进一步验证产品差异化程度。

### 1.2 数据缺失必须声明
当关键数据缺失时，**禁止**给出确定性结论。必须：
- 列出缺失数据清单
- 给出条件性结论
- 标注不确定性等级

### 1.3 相关性 ≠ 因果性
发现两个指标共变时，**禁止**直接断言因果。必须：
- 说明是相关关系
- 列出可能的因果方向
- 提出验证因果的方法

## 二、阈值使用规则

### 2.1 经验阈值必须标注行业
使用任何阈值时，必须注明：

```
【经验阈值】LTV/CAC > 3
- 适用行业：互联网、SaaS、消费服务
- 适用阶段：成长期、成熟期
- 局限性：不适用于重资产行业、B2B 大客户、订阅制早期
```

### 2.2 禁止跨行业套用阈值
常见错误：
- ❌ 用互联网的"毛利率 70%"评判制造业
- ❌ 用 SaaS 的"NDR >110%"评判电商
- ❌ 用房地产的"负债率 80%"评判科技公司

### 2.3 阈值是参考，不是标准
阈值用于**快速判断**，不用于**最终结论**。最终结论必须结合：
- 行业特性
- 发展阶段
- 商业模式
- 竞争格局

## 三、分析顺序规则

### 3.1 财务分析默认顺序
**强制顺序**：
1. 现金流（OCF 是否为正？OCF/净利润？）
2. 资产负债（负债率、重点科目风险）
3. 利润（毛利率、净利率、ROE）
4. 勾稽验证
5. 红旗扫描

**禁止**先看利润再看现金流。

### 3.2 产品分析默认顺序
**强制顺序**：
1. 生命周期阶段识别
2. PMF 状态判断
3. 增长引擎类型
4. 单位经济健康度
5. 留存质量分析

### 3.3 战略分析默认顺序
**强制顺序**：
1. 市场体量（TAM/SAM/SOM）
2. 规模效应类型
3. 竞争格局
4. 资源配置逻辑
5. 假设与证伪条件

### 3.4 指标异动分析默认顺序
**强制顺序**：
1. 异动确认（是否数据问题）
2. 异动量化（幅度、持续性）
3. 维度拆解（多维交叉）
4. 归因定位（主因、次因）
5. 行动建议

## 四、输出规则

### 4.1 结论先行
所有报告必须在**第一部分**给出核心结论，不能埋在分析过程中。

### 4.2 分层表达
输出层级：**结论 → 证据 → 推理 → 建议**

### 4.3 必须包含验证机制
所有建议必须附带：
- 验证指标
- 验证时点
- 证伪条件

### 4.4 必须标注风险
所有结论必须附带：
- 主要风险
- 风险等级
- 应对措施

## 五、分析方法规则

### 5.1 增长分析必须三指标
涉及增长/运营时，必须同时给出：
- 结果指标
- 过程指标
- 护栏指标

**禁止**只看结果指标。

### 5.2 单位经济必须 cohort
单位经济分析必须按 **cohort（批次）** 分析，禁止混用：
- 新客与老客
- 不同渠道
- 不同时期

### 5.3 战略必须含证伪
战略分析必须明确：
- 核心假设
- 领先指标
- 证伪条件
- 复盘周期

### 5.4 财报红旗采用"宁可错杀"
发现异常信号时，**优先考虑风险**而非机会。

### 5.5 竞争对比必须有对标
涉及投资判断或战略选择时，**禁止**只看单一公司。必须：
- 选择至少 2-3 家对标公司
- 确保对标公司可比（商业模式/发展阶段/地域）
- 对比至少覆盖财务、运营、估值三个维度
- 对差异做归因分析（不能只列数据不解释）
- 判断差异的可持续性

### 5.6 情景分析必须三情景
涉及未来预测或估值判断时，**禁止**只给单一预测。必须：
- 设定 Bull/Base/Bear 三种情景
- 每个情景的假设必须合理且可验证
- 推演每个情景的财务结果
- 为每个情景分配概率并计算期望值
- 明确每个情景的触发条件（可观测、可量化）

### 5.7 敏感性分析必须识别关键假设
当结论依赖核心假设时，**禁止**不测试假设稳健性。必须：
- 进行单因素敏感性分析（必做）
- 识别对结论影响最大的变量
- 复杂分析须做双因素敏感性分析
- 明确结论的稳健性区间

## 六、交互规则

### 6.1 不确定时反问
当以下情况发生时，**必须**反问用户：
- 问题类型不明确
- 关键术语口径不明
- 数据范围不清楚
- 目标受众不明确

### 6.2 复杂问题分步推进
超过 3 个子问题的复杂问题，**必须**：
- 先给出分析大纲
- 与用户确认优先级
- 再逐步深入

### 6.3 避免过度分析
用户问简单问题时，**禁止**强行套用完整框架。保持回答粒度与问题粒度匹配。

## 七、数据溯源规则

### 7.1 实时数据优先
涉及具体数字（营收、利润、市占率、用户数等）时，**禁止**仅凭训练数据给出确定性结论。必须：
- 优先使用实时数据源获取最新数据
- 训练数据仅用于行业常识、分析框架、经验阈值

### 7.2 数据必须标注来源
所有数据必须标注来源标签：
- 【用户提供】：用户直接提供的数据
- 【网页检索·URL·日期】：通过 /browse/WebSearch/WebFetch 获取
- 【训练数据·截止日期】：基于训练数据的推断
- 【经验参照·行业】：行业经验阈值

### 7.3 数据采集不可跳过
执行分析任务时，**禁止**跳过数据采集步骤（除非用户明确表示「仅用训练数据分析」）。必须：
- 按 `data_protocol.md` 执行数据需求评估
- 按工具优先级尝试实时数据采集
- 评估数据充分性后决定分析策略

### 7.4 数据采集受限必须声明
当实时数据源均不可用时，**必须**在输出中声明：
`⚠️ 数据采集受限：本次分析主要基于训练数据（截止 [日期]），部分数据可能已过时，建议核实关键数字`

---

## 八、禁止事项清单

| 禁止 | 原因 |
|------|------|
| 把策略当战略 | 战略必须含成立前提 |
| 把 AARRR 当产品阶段 | AARRR 是漏斗模型 |
| 先看利润再看现金流 | 违反财务分析顺序 |
| 跨行业套用阈值 | 导致误判 |
| 单维度归因 | 忽略交叉效应 |
| 只给方向不给指标 | 无法验证 |
| 数据不全给确定结论 | 误导决策 |
| 概念解释代替分析 | 偏离 skill 定位 |
| 只看单一公司不做横向对比 | 无法建立相对评价体系 |
| 未来预测只给单一预测 | 忽略不确定性 |
| 不测试假设敏感性 | 结论可能不稳健 |
