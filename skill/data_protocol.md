# 数据采集协议

本协议定义 senior_analyst skill 在执行分析任务时的数据采集流程。核心目标：**确保分析基于最新可得数据，而非仅依赖训练数据**。

---

## 一、核心原则

1. **实时数据优先**：凡涉及财务数据、市场数据、竞争格局等可能随时间变化的信息，优先使用实时数据源
2. **工具分层**：按可用性和可靠性选择数据采集工具，不依赖单一工具
3. **数据溯源**：所有数据必须标注来源和获取时间
4. **充分性门槛**：数据不足时，宁可降级分析范围，不做无依据的强结论

---

## 二、数据采集工具优先级

| 优先级 | 工具 | 适用场景 | 限制 |
|--------|------|---------|------|
| P0 | 用户直接提供 | 内部数据、私有数据、非公开信息 | 依赖用户输入 |
| P1 | senior_analyst MCP 工具 | 结构化财务/市场/竞品/宏观/加密数据查询（company_financials, company_profile, competitor_compare, market_data, news_search, industry_data, stock_news, **macro_data**, **crypto_data**） | 需 MCP server 已配置；多源 fallback 自动执行 |
| P2 | /browse (gstack) | 复杂网页浏览、年报下载、多页数据交叉验证 | 需要浏览器环境 |
| P3 | WebSearch | 快速事实查询、新闻搜索、市场数据检索 | 可能返回空结果或过时信息 |
| P4 | WebFetch | 已知 URL 的直接访问（年报、SEC filing、数据库） | 不适用于需认证的页面 |
| P5 | 训练数据 | 行业常识、经典理论、经验阈值、历史事实 | 可能过时，须标注截止日期 |

**使用规则**：
- P0-P4 统称「实时数据源」，P5 为「训练数据源」
- **senior_analyst MCP 工具（P1）为首选实时数据源**，提供结构化查询，比搜索式工具（P2-P4）更可靠
- 凡涉及具体数字（营收、利润、市占率、用户数、宏观指标、加密价格等），**禁止**仅凭训练数据给出确定性结论
- 训练数据仅用于：行业常识、分析框架、经验阈值、历史已验证事实

### 置信度评分（v1.8+）

所有 MCP 工具返回的 JSON 中包含 `confidence` 字段，结构如下：

```json
{
  "score": 0.85,
  "source_count": 2,
  "source_agreement": 1.0,
  "data_freshness": "real-time",
  "anomalies": [],
  "notes": "agreement=1.00, freshness=real-time, completeness=1.00, anomalies=0"
}
```

**使用规则**：
- score ≥ 0.9：可直接引用数据，无需额外验证
- score 0.7-0.89：可引用但须标注置信度
- score 0.5-0.69：需 WebSearch 补充验证
- score < 0.5：数据不可信，不引用

**交叉验证**：`company_financials` 自动尝试双源交叉验证，返回 `cross_validation` 字段含偏差分析。
**深度验证**：用 `validate_financials` 做三表勾稽 + 异常检测。

### Council 审查与置信度交互（v1.9+）

v1.8 的置信度评分解决"数据对不对"，v1.9 的 Council 审查解决"结论该不该下"。两者交叉标注：

| 数据置信度 | Council 结果 | 综合判断 | 标注方式 |
|-----------|-------------|---------|---------|
| ≥0.9 | 无分歧 | 结论可信，直接引用 | 无额外标注 |
| ≥0.9 | 有分歧 | 数据可靠但解读有争议 | `数据置信度: 0.85 | Council: 分歧` |
| <0.7 | 无分歧 | 数据弱但逻辑一致 | `数据置信度: 0.65 | Council: 一致` |
| <0.7 | 有分歧 | 最弱组合 — 标注双重风险 | `数据置信度: 0.65 | Council: 分歧 ⚠️` |

Council 审查不影响数据层的置信度评分，但会揭示证据等级的**使用是否恰当**：Red Team 可能指出一个 L4（推断）被当作 L1（事实）使用。

### MCP 健康自检

任何时候可运行 `senior_analyst-doctor` 自检 Tier 0/Tier 1 数据源状态。当用户报告"数据源不可用/不准确"时，**第一步**就是建议运行此命令。

### 配置 API key

`senior_analyst-setup-keys` 提供交互式向导。可选 key 及其解锁能力：
- **FRED**（免费，30 秒注册）→ 美国宏观经济数据
- **FMP**（付费，14 美元/月起）→ 全球公司财报增强 + 同业推荐
- **Alpha Vantage**（免费，25 req/day）→ 全球股票基本面
- **NewsAPI**（免费，100 req/day dev）→ 英文新闻
- **CoinGecko Pro**（付费可选）→ 加密高级数据

## 三、按任务类型的数据需求清单

### 指标异动诊断

必要数据（缺任何一项，降级为「条件性分析」）：
- 异动指标的时间序列数据（至少 4 周）
- 同期对比数据（YoY/QoQ）
- 维度拆解数据（渠道/地区/用户类型）

补充数据：
- 外部环境变化（政策/竞品/季节性）
- 技术变更记录（发版/配置/基础设施）

### 商业模式/单位经济评估

必要数据：
- 收入结构及变化趋势（至少 2 年）
- 成本结构（COGS/运营费用/研发费用占比）
- 客户获取成本（CAC）和生命周期价值（LTV）
- 毛利率/净利率趋势

补充数据：
- 竞品商业模式及单位经济对比
- 行业标杆单位经济
- 客户留存和复购数据

### PMF/增长诊断

必要数据：
- 留存率（次日/7日/30日）
- 用户增长趋势（至少 6 个月）
- 获客渠道及各渠道 CAC

补充数据：
- NPS/用户满意度
- 口碑传播指标（K因子/病毒系数）
- 核心功能使用率

### 战略分析

必要数据：
- 市场规模（TAM/SAM/SOM）
- 竞争格局及市场份额
- 目标市场增长趋势

补充数据：
- 政策/监管环境
- 技术趋势和替代威胁
- 进入壁垒分析

### 财报分析/排雷

必要数据：
- 最近 2-3 年三大报表（利润表/资产负债表/现金流量表）
- 现金流量表详细科目
- 关键财务比率（ROE/毛利率/净利率/负债率/OCF 等）

补充数据：
- 管理层讨论与分析（MD&A）
- 审计报告及审计意见
- 同行业财务对比
- 前五大客户/供应商集中度

### 竞争对手对比

必要数据：
- 目标公司及对标公司核心财务数据
- 对标公司运营数据（MAU/订单量/GTV 等）
- 估值水平对比（P/S/P/E/EV/EBITDA 等）

补充数据：
- 竞品产品功能对比
- 市场份额变化趋势
- 供应链/渠道对比

### 情景/敏感性分析

必要数据：
- 历史财务数据（至少 3 年，用于趋势推演）
- 关键驱动因素的历史数据
- 行业预测数据

补充数据：
- 卖方分析师预测
- 宏观经济数据
- 公司指引（guidance）

### 宏观经济分析（v1.7+）

必要数据（用 `macro_data` 工具采集）：
- GDP 增速时间序列（至少 3 年）
- CPI / PPI 通胀指标（最近 12-24 个月）
- 失业率（最近 12 个月）

补充数据：
- 利率水平（10Y 国债、政策利率）
- M2 货币供应增速
- PMI 工业景气
- 进出口/贸易差额

**支持的 region**：US, CN, EU, JP, UK, DE, FR, IN, global。US 推荐配 FRED key 解锁高频数据。

### 加密资产/Web3 分析

必要数据（用 `crypto_data` 工具采集）：
- 头部币种价格、市值、24h 量
- 流通量、最大供应（如有）

补充数据：
- 监管/ETF 资金流向新闻（用 `news_search`）
- 链上数据（TVL、地址数）→ 暂不在 MCP 范围，需 /browse 补充

## 四、数据采集流程（强制执行）

### Phase 1: 数据需求评估

1. 根据任务类型，从第三节加载对应数据需求清单
2. 检查用户已提供的数据，标记已满足项
3. 识别数据缺口，区分「必要数据缺口」和「补充数据缺口」
4. 向用户展示数据缺口摘要（如有必要数据缺口，**必须**展示）

### Phase 2: 实时数据采集

按工具优先级依次尝试。**此步骤不可跳过**（除非用户明确表示「仅用训练数据分析」）。

**Step A: /browse（首选）**

对以下数据源进行浏览（按需选择）：
- 上市公司：公司投资者关系页面（年报/季报/投资者演示文稿）
- 行业数据：行业数据平台、咨询公司报告
- 新闻：财经媒体对目标公司的最新报道

**Step B: WebSearch（次选）**

对数据缺口逐项搜索，推荐查询格式：
- `"[公司名]" "[年度/季度]" "年报" OR "财报" OR "季报"`
- `"[公司名]" "[指标名]"`（如 "滴滴 GTV 2025"）
- `"[行业名]" "市场规模" OR "行业报告"`
- `"[公司名]" "竞争对手" OR "对标"`

**Step C: WebFetch（定向获取）**

若已知具体 URL，直接获取：
- SEC EDGAR: `https://www.sec.gov/cgi-bin/browse-edgar?action=getcompany&company=[公司名]`
- 港交所披露易: `https://www.hkexnews.hk/`
- 公司投资者关系页面

**采集失败处理**：
- 若所有实时数据源均不可用，**必须**在输出中明确声明
- 声明格式：`⚠️ 数据采集受限：本次分析主要基于训练数据（截止 [日期]），部分数据可能已过时，建议核实关键数字`

### Phase 3: 数据充分性评估

| 充分性等级 | 标准 | 分析策略 |
|-----------|------|---------|
| **充分** | >80% 必要数据已通过实时源获取 | 正常推进全量分析 |
| **部分充分** | 50-80% 必要数据已获取，其余可由训练数据+合理假设补充 | 条件性分析，明确标注数据缺口和假设 |
| **不充分** | <50% 必要数据已获取 | 暂停分析，向用户说明：1) 数据缺口清单 2) 建议的补充方式 3) 若继续的分析风险 |

### Phase 4: 数据溯源标注

所有使用的数据必须标注来源标签：

| 来源标签 | 含义 | 标注格式 |
|---------|------|---------|
| 【用户提供】 | 用户直接提供的数据 | `【用户提供】` |
| 【网页检索·URL·日期】 | 通过 /browse/WebSearch/WebFetch 获取 | `【网页检索·sec.gov·2026-04-21】` |
| 【训练数据·截止日期】 | 基于训练数据的推断 | `【训练数据·截至2025-04】` |
| 【经验参照·行业】 | 行业经验阈值 | `【经验参照·SaaS行业】` |

**标注示例**：
```
【事实·网页检索·ir.didiglobal.com·2026-04-21】滴滴 2025 年全年收入 2,023 亿元，同比增长 6%
【事实·训练数据·截至2025-04】滴滴 2024 年 GTV 约 3,500 亿元
【经验·出行行业】Take Rate 6-8% 为中国出行平台正常区间
```

## 六、特殊场景处理

### 场景 1: 用户要求「快速分析」

当用户要求快速给出判断时：
- 仍需执行 Phase 1（数据需求评估），但可简化
- 跳过 Phase 2 的 Step A（/browse），直接用 WebSearch
- 若 WebSearch 不可用，用训练数据，但**必须**在结论前加注：`⚡ 快速分析模式：基于训练数据，关键数字请核实`

### 场景 2: 分析过程中发现数据缺口

在 Step 4（分析推进）中发现新的数据需求时：
1. 暂停分析
2. 返回 Phase 2 补充采集
3. 采集后再继续
4. 在输出中标注「分析过程中补充采集」的数据

### 场景 3: 数据冲突

当不同来源的数据存在矛盾时：
1. 列出所有来源及其数据
2. 评估各来源可靠性（官方财报 > 权威媒体 > 个人博客）
3. 采用更可靠来源的数据
4. 标注冲突和选择理由
5. 若无法判断，列出两种可能，由用户确认

### 场景 4: 数据量过大

当搜索返回大量数据时：
1. 优先提取与核心分析维度最相关的数据
2. 保存关键数据点，放弃细节数据
3. 在输出中标注「部分数据因篇幅限制未展示」

### 场景 5: 非上市公司数据不透明

当分析对象为非上市公司或业务数据不公开时：
1. **关联公司数据反推**：查找参股/控股/合资公司的公开财务数据，基于持股比例和业务关系推算
   - 示例：滴滴持有杭银消金33.34%→从杭银消金公开财报反推滴滴金融贡献
   - 示例：参股保险公司→从保险公司在银保监会的公开数据推算
2. **行业标杆对标**：找到同行业可比上市公司的公开数据作为参照
3. **监管公示数据**：从小贷公司增资、消金公司财报、ABS发行说明书等监管文件获取
4. **投诉平台数据**：从黑猫投诉、消费保等平台获取用户侧间接数据（投诉量、投诉类型）
5. 所有推算数据必须标注推算逻辑和不确定性区间

## 七、参考来源规范

### 最低要求
所有分析报告必须在末尾附参考来源表，不可仅用笼统声明（如"来源：搜狐、新浪财经"）。

### 格式
| 编号 | 来源名称 | URL | 引用内容 | 访问日期 |
|------|---------|-----|---------|---------|
| 1 | ... | ... | ... | ... |

### 来源分级
| 级别 | 来源类型 | 优先使用 | 示例 |
|------|---------|---------|------|
| A | 官方文件 | 是 | 公司年报、监管批复、ABS说明书 |
| B | 权威媒体 | 是 | 财新、36氪、证券时报、新华网 |
| C | 行业媒体 | 是 | 未央网、亿欧、蓝鲸财经 |
| D | 自媒体/博客 | 谨慎 | 搜狐号、网易号、雪球 |
| E | 用户生成内容 | 仅作辅助 | 黑猫投诉、知乎回答 |

### 采集时记录
在 Phase 2 数据采集过程中，**每获取一条有效数据，同时记录来源 URL**。不要等到分析完成后补找来源。
