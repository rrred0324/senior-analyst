# 证据等级规范

本文档定义 skill 在输出分析时对每个判断应标注的证据等级。

## 四级证据体系

| 等级 | 含义 | 标注符号 | 使用场景 |
|------|------|---------|---------|
| **L1** | 公认事实/数据直接支撑 | 【事实】 | 来自财报、埋点数据、可验证文件 |
| **L2** | 行业共识/经典理论 | 【共识】 | 波特五力、PMF 理论、杜邦分解 |
| **L3** | 经验阈值/常用做法 | 【经验】 | LTV/CAC>3、OCF/净利润>0.8 |
| **L4** | 推断/假设/个人观点 | 【推断】 | 基于已知信息的合理推测 |

## 标注示例

### 完整报告示例片段

```markdown
## 关键发现

### 发现 1：公司现金流存在异常
【事实】公司 2023 年净利润 5 亿，但经营现金流仅 1.2 亿，OCF/净利润 = 0.24。
【经验】OCF/净利润 <0.5 通常意味着盈利质量较差，需深入调查。
【推断】结合应收账款增速 45% 远超营收增速 20%，可能存在放松信用政策换收入的情况，建议进一步核查前五大客户账期变化。

### 发现 2：商业模式存在规模效应
【共识】网络效应型业务在过临界点后呈现赢家通吃特征（Metcalfe 定律）。
【事实】公司 MAU 已突破 5000 万，为行业第一。
【推断】公司可能已过临界点，竞争壁垒在加深，但需关注是否存在多归属（Multi-homing）风险。
```

## 使用规则

### 1. 每个核心判断必须标注
核心判断 = 直接影响最终结论的观点

### 2. 证据等级决定结论强度
- L1 + L2 → 可给出强结论
- L1 + L3 → 可给出条件性结论
- L3 + L4 → 只能给出假设/建议

### 3. 禁止混淆等级
**错误**：把经验阈值当事实
> "公司 LTV/CAC = 2，说明商业模式不健康。"

**正确**：
> 【事实】公司 LTV/CAC = 2。
> 【经验】互联网行业 LTV/CAC > 3 通常被认为健康。
> 【推断】在互联网场景下，当前单位经济偏弱；但若公司属于重资产或长周期行业，2 也可能是正常水平，需结合行业定位判断。

### 4. 推断必须说明依据
所有 L4 级推断必须说明：
- 基于什么信息
- 哪些是已知，哪些是假设
- 如何进一步验证

## 特殊情况

### 数据不足时
如果某判断的证据等级降至 L4 以下（即纯猜测），**禁止**输出该判断，改为：
- 列入"数据缺口"
- 转为开放式问题
- 提出补数据建议

## 数据溯源标签

在证据等级之外，每个数据点还必须标注来源标签。来源标签与证据等级正交（一个 L1 事实可以来自网页检索，也可以来自用户提供）。

| 来源标签 | 含义 | 标注格式 |
|---------|------|---------|
| 用户提供 | 用户直接提供的数据 | `【用户提供】` |
| 网页检索 | 通过 /browse/WebSearch/WebFetch 获取 | `【网页检索·域名·日期】` |
| 训练数据 | 基于训练数据的推断 | `【训练数据·截至YYYY-MM】` |
| 经验参照 | 行业经验阈值 | `【经验参照·行业名】` |

### 组合标注示例

```
【事实·网页检索·ir.didiglobal.com·2026-04-21】滴滴 2025 年全年收入 2,023 亿元，同比增长 6%
【事实·训练数据·截至2025-04】滴滴 2024 年 GTV 约 3,500 亿元
【经验·出行行业】Take Rate 6-8% 为中国出行平台正常区间
【推断·训练数据·截至2025-04】滴滴国际业务保险渗透率预计可达 8-12%
```

### 标注规则

1. **L1（事实）+ 网页检索**：最强证据组合，可给出确定性结论
2. **L1（事实）+ 训练数据**：结论需加注「数据可能已更新，请核实」
3. **L1（事实）+ 用户提供**：可信度取决于用户数据来源
4. **L4（推断）+ 训练数据**：最弱组合，只能作为假设/方向参考

### 存在争议时
当同一问题存在不同理论/观点时：
- 列出主流观点
- 说明各自适用条件
- 不强行选边
