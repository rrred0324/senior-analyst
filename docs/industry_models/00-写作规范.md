# 行业分析写作规范

> 用途：统一行业研究、商业建模、投资尽调、公司对比三类文件的写作风格、结构、口径和输出质量
> 适用范围：知识库中所有行业文件
> 适用对象：研究员、投资经理、分析师、行业专家、AI 生成内容校对
> 配套母模板：
> - 00-商业建模总模板.md
> - 00-投资尽调总模板.md
> - 00-公司对比总模板.md

---

# 一、写作目标

所有行业分析文件必须做到以下四点：

## 1.1 统一结构
不同赛道可以不同，但分析逻辑必须一致：
- 先定义行业
- 再讲商业本质
- 再拆收入成本
- 再看指标
- 再谈壁垒和风险
- 最后落到投资判断

## 1.2 统一口径
避免同一概念在不同文件中表达不一致，如：
- GMV、收入、流水混用
- 用户数、活跃用户、付费用户不区分
- 留存、复购、续费口径混乱
- 毛利率与净利率混淆

## 1.3 统一粒度
每份文件都要尽量回答同一层级的问题：
- 行业是什么
- 公司怎么赚钱
- 增长靠什么
- 成本卡在哪里
- 壁垒在哪里
- 风险在哪里

## 1.4 统一输出标准
任何文件都应支持三种使用场景：
- 快速阅读：能 3 分钟看懂本质
- 深度研究：能顺着结构继续补充
- 横向比较：能和其他行业或公司对齐

# 二、文件分类规范

知识库文件统一分为三大类：

## 2.1 商业建模类
用于理解"这个行业本质是什么、怎么赚钱、核心指标是什么"

### 典型文件
- 行业商业建模
- 行业一页纸速查卡
- 行业研究框架
- 行业投资地图

### 对应母模板
- 00-商业建模总模板.md

## 2.2 尽调类
用于研究"某个公司值不值得投、该验证什么、风险是什么"

### 典型文件
- 行业投资尽调模板
- 专题尽调清单
- 管理层访谈问题
- 投委会问题清单

### 对应母模板
- 00-投资尽调总模板.md

## 2.3 对比类
用于研究"多个公司谁更强、差异在哪、应该投谁"

### 典型文件
- 公司对比模板
- 竞品对比
- 细分赛道对比
- 打分卡

### 对应母模板
- 00-公司对比总模板.md

# 三、命名规范

## 3.1 文件命名格式

### 标准格式
```text
编号-行业名称-文件类型.md
```

### 示例
+ 12-SaaS行业商业建模.md
+ 35-跨境电商行业投资尽调模板.md
+ 68-企业服务行业公司对比模板.md

## 3.2 母模板命名格式
所有全行业通用模板统一以 `00-` 开头：

+ 00-商业建模总模板.md
+ 00-投资尽调总模板.md
+ 00-公司对比总模板.md
+ 00-写作规范.md

## 3.3 文件类型命名统一词表
建议固定使用以下名称，避免随意变化：

### 推荐标准名称
+ 商业建模
+ 一页纸速查卡
+ 投资尽调模板
+ 公司对比模板
+ 行业研究框架
+ 行业投资地图
+ 管理层访谈清单
+ 投委会摘要

### 不建议混用的名称
避免同义乱写，如：

+ "研究提纲""分析模版""赛道框架""基础版模板"
除非有明确功能差异，否则尽量统一。

# 四、标题层级规范
## 4.1 标题层级统一
统一使用如下层级：

```markdown
# 一级标题
## 二级标题
### 三级标题
```

原则上：

+ 一级标题：文件名
+ 二级标题：核心模块
+ 三级标题：模块内细分内容

## 4.2 标题数量控制
建议：

+ 一级标题：1个
+ 二级标题：10-16个
+ 三级标题：每部分 2-6 个

避免：

+ 标题过深（四级、五级标题太多）
+ 标题过碎，导致文档像 checklist 而不像分析框架

## 4.3 标题命名风格
使用"名词型标题"，尽量避免口语化标题。

### 推荐
+ 行业本质
+ 收入模型
+ 成本结构
+ 竞争格局
+ 风险分析

### 不推荐
+ 这个行业到底是怎么回事
+ 为什么它能赚钱
+ 我们应该怎么看它

---

# 五、写作风格规范
## 5.1 先结论，后展开
每个重要部分，优先给出一句核心判断，再展开说明。

### 推荐写法
> 该行业的核心不是规模本身，而是规模背后的单位经济是否成立。
>

然后再补：

+ 为什么
+ 如何判断
+ 看什么指标

## 5.2 句式要短，逻辑要硬
尽量写成投资判断语言，而不是宣传语言。

### 推荐
+ 行业增长快，但毛利率不稳定。
+ 该模式收入可见性强，但交付较重。
+ 核心壁垒来自供给控制，而非流量。

### 不推荐
+ 该公司拥有非常优秀且极具前瞻性的商业模式。
+ 该赛道未来发展潜力巨大，值得重点关注。

## 5.3 少空话，多变量
每一段尽量落到：

+ 变量
+ 机制
+ 指标
+ 风险

### 推荐表达
+ 增长主要取决于 CAC 是否低于 LTV。
+ 平台粘性取决于供需两端是否形成正循环。
+ 毛利率改善取决于标准化率和交付效率。

## 5.4 少"趋势判断"，多"结构判断"
趋势可以写，但必须落到结构：

+ 是什么结构导致增长
+ 是什么结构导致利润
+ 是什么结构导致壁垒
+ 是什么结构导致风险

# 六、定义与口径规范
## 6.1 收入相关口径
### 收入（Revenue）
公司确认到利润表的营业收入。

### GMV（Gross Merchandise Volume）
平台撮合成交总额，不等于公司收入。

### TPV（Total Payment Volume）
支付总交易额，不等于公司净收入。

### 流水
泛指交易额或充值额，必须明确是否等同 GMV / TPV / 总充值。

### take rate
```latex
take rate = 平台收入 / 平台撮合交易额
```

---

## 6.2 用户相关口径
### 注册用户
历史注册过的总用户。

### 活跃用户
在某一统计周期内有过活跃行为的用户。

### DAU / MAU
日活/月活，必须明确统计口径。

### 付费用户
统计周期内有过付费行为的用户。

### ARPU
```latex
ARPU = 某周期收入 / 总活跃用户数
```

### ARPPU
```latex
ARPPU = 某周期收入 / 付费用户数
```

---

## 6.3 B端客户口径
### 客户数
实际签约并贡献收入的企业数量，需区分：

+ 累计客户数
+ 当前活跃客户数
+ 付费客户数

### ACV
```latex
ACV = 单客户年合同金额
```

### NRR
```latex
NRR = 期初客户在本期续费+扩单收入 / 期初客户收入
```

### GRR
```latex
GRR = 期初客户续费收入 / 期初客户收入
```

---

## 6.4 留存与复购口径
### 留存率
某批用户在之后某周期仍活跃的比例。

### 复购率
购买后再次购买的用户比例。

### 续费率
订阅客户到期后继续付费的比例。

### 回流率
流失后再次活跃/购买的用户比例。

---

## 6.5 成本与利润口径
### 毛利率
```latex
毛利率 = （收入 - 主营业务成本）/ 收入
```

### 经营利润率
```latex
经营利润率 = 经营利润 / 收入
```

### CAC
```latex
CAC = 获客总成本 / 新增付费客户数
```

### LTV
```latex
LTV = 单客户生命周期总毛利贡献
```

### CAC 回收周期
```latex
CAC 回收周期 = 获客成本 / 月度毛利贡献
```

# 七、公式写法规范
## 7.1 所有公式单独成块
统一使用代码块，避免正文内混杂。

### 标准格式
```latex
收入 = 用户数 × 付费率 × ARPPU
```

## 7.2 公式从总到分
先给总公式，再拆因子。

### 示例
```latex
收入 = GMV × take rate
GMV = 购买用户数 × 购买频次 × 客单价
```

## 7.3 同一文件内变量命名保持一致
例如：

+ 不要同时写"客单价 / AOV / 平均订单金额"
+ 选一个主表达，其余首次出现时备注即可

---

# 八、指标体系写法规范
## 8.1 指标必须分层
不能把所有指标堆在一起，必须按层组织：

+ 规模指标
+ 增长指标
+ 转化指标
+ 留存/复购指标
+ 变现指标
+ 供给指标
+ 效率指标
+ 财务指标
+ 风险指标

## 8.2 指标必须服务于判断
列指标不是目的，关键是回答：

+ 为什么看这个指标？
+ 指标高低说明什么？
+ 它和收入、利润、壁垒的关系是什么？

### 推荐写法
+ 30日留存决定该产品是否具备稳定使用价值。
+ NRR 用于判断 B 端客户是否会自发扩张。
+ take rate 反映平台议价能力和变现深度。

## 8.3 每个行业保留"3-5个一级关键指标"
不要所有指标都当核心。必须明确真正重要的少数指标。

示例格式：

### 本行业最关键的 5 个指标
1.
2.
3.
4.
5.

# 九、商业分析文件写法规范
## 9.1 必须包含的模块
1. 行业定义
2. 行业本质
3. 分类与细分赛道
4. 商业模式
5. 收入模型
6. 成本结构
7. 核心指标
8. 竞争格局
9. 壁垒
10. 风险
11. 市场空间
12. 一句话结论

## 9.2 一页纸文件写法
一页纸不是删内容，而是压缩到最关键变量：

+ 行业本质
+ 核心公式
+ 核心指标
+ 核心判断问题
+ 最大风险
+ 一句话结论

# 十、尽调文件写法规范
## 10.1 尽调不是行业介绍
尽调文件重点不是"行业多大"，而是：

+ 公司是不是真的解决问题
+ 数据是否成立
+ 增长是否可持续
+ 财务是否健康
+ 风险是否可控

## 10.2 尽调问题写法
每个问题尽量是"可验证"的，而不是泛泛发问。

### 推荐
+ 最近 12 个月客户续费率是多少？
+ 前 20 大客户收入占比是多少？
+ 若停止补贴，订单量预计下降多少？

### 不推荐
+ 你们的客户满意吗？
+ 你们未来怎么增长？
+ 你们有没有壁垒？

## 10.3 尽调结论必须分三类
+ 已验证成立
+ 尚需验证
+ 明确风险点

---

# 十一、对比文件写法规范
## 11.1 对比必须统一口径
不同公司比较时，必须尽量统一：

+ 时间周期
+ 指标定义
+ 收入确认方式
+ 是否含税
+ 是否合并口径

## 11.2 对比要分"事实"和"判断"
### 事实
+ 收入规模
+ 毛利率
+ 留存率
+ CAC
+ NRR

### 判断
+ 产品壁垒更强
+ 组织更成熟
+ 扩张能力更好

不能只写判断，不写事实支撑。

## 11.3 最后必须输出"谁更优，为什么"
不是简单列表，而是要得出结论：

+ 谁当前最强
+ 谁增长更快
+ 谁壁垒更深
+ 谁风险更大
+ 谁最值得投

---

# 十二、风险写法规范
## 12.1 风险必须具体
### 推荐
+ 收入增长依赖前三大客户，客户集中度过高。
+ 当前单城模型尚未盈利，扩张存在复制不成立风险。
+ 付费率提升来自强商业化，可能压制长期留存。

### 不推荐
+ 市场竞争激烈
+ 存在一定不确定性
+ 未来发展可能不及预期

## 12.2 风险最好对应预警指标
示例：

+ 风险：回款恶化
+ 预警指标：DSO 连续两个季度上升
+ 风险：留存下滑
+ 预警指标：30日留存连续 3 个月下跌

---

# 十三、结论写法规范
## 13.1 结论必须可投资使用
结论至少回答以下问题：

1. 这个行业/公司值不值得看？
2. 最重要的判断抓手是什么？
3. 最大风险是什么？
4. 下一步该验证什么？

## 13.2 推荐结论模板
### 商业建模结论
> 该行业本质上是一个________行业，核心价值来自________，长期胜负手不是________，而是________。
>

### 尽调结论
> 该公司当前最值得关注的点在于________，但要成立投资逻辑，仍需验证________；最大风险在于________。
>

### 对比结论
> 横向比较看，公司A 在________上领先，公司B 在________上更优，若以当前阶段投资优先级排序，建议________。
>

---

# 十四、质量检查清单
在文件入库前，至少检查以下问题：

## 14.1 结构检查
+ 是否符合对应母模板结构？
+ 是否有明确结论？
+ 是否从行业本质推到经营指标？

## 14.2 口径检查
+ 指标定义是否一致？
+ GMV、收入、流水是否区分？
+ 留存、复购、续费是否区分？

## 14.3 内容检查
+ 是否存在大量空话？
+ 是否有无法验证的主观判断？
+ 是否缺少关键公式？
+ 是否缺少核心风险？

## 14.4 投资可用性检查
+ 投资经理是否能直接拿去开会？
+ 是否支持横向比较？
+ 是否能快速提炼判断？

---

# 十五、一句话总原则
> 所有行业分析文件都要从"概念介绍"升级为"商业机制说明"，从"信息罗列"升级为"投资判断工具"。
>
