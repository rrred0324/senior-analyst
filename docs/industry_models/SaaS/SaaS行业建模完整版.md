# 一、行业基础定义

## 1.1 行业名称
- 行业名称：SaaS（Software as a Service）
- 细分赛道：水平 SaaS、垂直 SaaS、工具型 SaaS、流程型 SaaS、平台型 SaaS
- 上下游位置：
  - 上游：云基础设施、数据库、中间件、开发框架、渠道生态、咨询实施伙伴
  - 中游：SaaS 软件提供商
  - 下游：企业客户、政府机构、组织用户
- 主要服务对象：以 To B 为主，部分为 To G / To SMB / To C-prosumer

## 1.2 行业一句话定义
> SaaS 行业的本质是：以持续订阅方式向客户提供可快速部署、持续迭代的软件服务，帮助客户提升效率、规范流程、沉淀数据或完成数字化经营，并通过订阅费、模块费、实施费和增值服务实现商业化。

## 1.3 行业边界

### 覆盖范围
- 标准化软件订阅产品
- 云端部署或以云为主的软件服务
- 企业管理、业务协同、经营分析、客户管理、财务、人力、营销、供应链等 SaaS 业务
- 以年度或月度订阅为核心收入形态的软件产品

### 不覆盖范围
- 纯项目制软件外包
- 以硬件收入为主的软件附属业务
- 一次性 License 为主的传统本地化软件
- 与 SaaS 无订阅关系的 IT 集成服务

# 二、行业本质与核心价值

## 2.1 商业本质

SaaS 的核心不是“卖软件”，而是：

> 以更低部署门槛和持续服务方式，持续嵌入客户业务流程，并通过长期续费与扩模块实现累计收入增长。

### 1）客户为什么需要它？
客户采购 SaaS，通常是为了解决以下问题：
- 流程依赖人工，效率低
- 组织协同成本高
- 数据分散，经营不可视
- 管理标准化不足
- 传统软件部署慢、维护重、升级难
- 业务线上化和数字化需求提升

### 2）企业提供的核心价值是什么？
- 流程数字化
- 协同效率提升
- 管理标准化
- 数据可视化和决策支持
- 降低 IT 运维负担
- 更快上线与持续迭代
- 在客户组织中形成经营基础设施属性

### 3）企业为什么能赚钱？
SaaS 公司之所以能赚钱，不是因为单次售卖，而是因为：
- 客户持续订阅
- 客户从低配版本升级到高配版本
- 用户数、模块数、使用量扩大
- 增值服务（实施、培训、咨询、API、生态分成）带来追加收入
- 客户切换成本提升后，续费和提价能力增强

## 2.2 价值创造链条

SaaS 行业的典型经营链路为：

```text
发现客户需求
→ 产品设计与开发
→ 获客（销售/渠道/内容/生态）
→ 演示与试用
→ 首次付费签约
→ 上线实施与培训
→ 客户使用与嵌入流程
→ 续费与扩模块
→ NRR提升
→ 收入和毛利释放
```

## 2.3 行业核心飞轮
SaaS 的核心飞轮通常是：

```latex
更多客户使用
→ 更多业务数据与场景沉淀
→ 产品更完善、模板更成熟
→ 实施效率更高、客户价值更强
→ 更高续费率与扩单率
→ 更多收入投入产品和销售
→ 更多客户使用
```

对优秀 SaaS 公司而言，真正强的飞轮不是“多销售”，而是：

> 产品嵌入更深 → 续费更强 → 扩单更自然 → 单客户价值不断上升。
>

# 三、行业分类与细分赛道
## 3.1 一级分类
### 按客户覆盖范围
+ 水平 SaaS：适用于多数行业，如 CRM、协同办公、费控、HR
+ 垂直 SaaS：服务单一行业，如餐饮 SaaS、教育 SaaS、医疗 SaaS、零售 SaaS

### 按功能属性
+ 工具型 SaaS：解决单点问题，如电子签、表单、项目管理
+ 流程型 SaaS：嵌入核心业务流程，如 ERP、财务、人力、供应链
+ 数据型 SaaS：分析、BI、营销归因、经营分析
+ 平台型 SaaS：开放 API、集成多模块、构建生态

### 按客户体量
+ SMB SaaS：中小企业客户，标准化高、客单价低
+ Mid-market SaaS：中型客户，适度定制
+ Enterprise SaaS：大客户，客单价高、实施重、销售周期长

## 3.2 细分赛道表
| 细分赛道 | 定义 | 核心客户 | 核心需求 | 收入模式 | 关键指标 |
| --- | --- | --- | --- | --- | --- |
| 协同办公 SaaS | 解决内部沟通协作与项目协同 | 各类企业 | 提升组织协同效率 | 订阅费 + 增值模块 | MAU、席位数、续费率 |
| CRM / 销售管理 SaaS | 管理客户、线索、销售流程 | 销售驱动企业 | 提升转化和客户管理效率 | 订阅费 + 席位费 | ACV、NRR、使用深度 |
| ERP / 经营管理 SaaS | 管理采购、库存、财务、经营流程 | 中大型企业 | 流程标准化、数据一体化 | 订阅费 + 实施费 | ACV、实施周期、续费率 |
| 垂直行业 SaaS | 面向特定行业场景 | 行业企业 | 行业化流程支持 | 订阅费 + 交易/支付/服务费 | 行业渗透率、复购、交叉销售 |
| 开发工具 SaaS | 面向开发者或技术团队 | 技术团队 | 提升研发效率 | 订阅费 + 使用量计费 | DAU、留存、Usage-based 收入 |


## 3.3 不同赛道差异点
+ 水平 SaaS：市场更大，但竞争更强
+ 垂直 SaaS：行业 know-how 更强，但市场空间相对更窄
+ SMB SaaS：标准化高，但流失率可能更高
+ 企业级 SaaS：客单价高，但交付重、销售周期长
+ 工具型 SaaS：易切入，但壁垒可能偏弱
+ 流程型 SaaS：切得慢，但一旦嵌入流程，粘性更强

# 四、商业模式分类
## 4.1 主要收入模式
### 模式一：订阅收费
+ 名称：Subscription
+ 收费对象：企业客户
+ 收费方式：按年或按月订阅
+ 公式：

```latex
订阅收入 = 付费客户数 × 平均订阅单价
```

### 模式二：按席位收费
+ 名称：Seat-based
+ 收费对象：使用员工/账户
+ 收费方式：按账号数或席位数收费
+ 公式：

```latex
收入 = 客户数 × 平均席位数 × 单席位价格
```

### 模式三：按模块收费
+ 名称：Module-based
+ 收费对象：企业客户
+ 收费方式：基础模块 + 高级模块 separately 收费
+ 公式：

```latex
收入 = 客户数 × 平均购买模块数 × 模块单价
```

### 模式四：按使用量收费
+ 名称：Usage-based
+ 收费对象：企业客户
+ 收费方式：按调用量、数据量、交易量、消息量等计费
+ 公式：

```latex
收入 = 使用量 × 单位价格
```

### 模式五：实施与服务收费
+ 名称：Service / Implementation
+ 收费对象：企业客户
+ 收费方式：一次性实施、培训、咨询、定制开发
+ 公式：

```latex
服务收入 = 项目数 × 平均服务合同额
```

## 4.2 行业最优商业模式
SaaS 理想的最优模型通常具备以下特征：

+ 经常性订阅收入占比高
+ 标准化程度高
+ 实施交付轻
+ NRR 高于 100%
+ 毛利率高
+ CAC 可被长期客户价值覆盖

也就是说，最优的 SaaS 模型不是：

> “先签很多大单”
>

而是：

> “以标准化产品切入，形成高续费和高扩单的长期复利型收入结构”。
>

## 4.3 从单点收费到综合变现路径
```latex
免费试用/低价切入
→ 基础订阅收费
→ 高级模块收费
→ 席位扩张
→ API / 生态 / 数据服务
→ 实施、培训、咨询
→ 平台化增值收入
```

# 五、收入模型
## 5.1 总收入公式
```latex
总收入 = 订阅收入 + 席位收入 + 模块收入 + 使用量收入 + 实施服务收入 + 其他增值收入
```

## 5.2 拆解驱动因子
### 通用 SaaS 收入拆法
```latex
收入 = 客户数 × ACV
```

进一步拆为：

```latex
ACV = 基础订阅价格 + 席位费用 + 模块费用 + 增值服务费用
```

如果强调存量扩张：

```latex
本期收入 = 期初客户续费收入 + 存量客户扩单收入 + 新增客户收入
```

如果强调经营质量：

```latex
收入增长 = 新增客户增长 + 提价增长 + 扩模块增长 - 客户流失影响
```

## 5.3 收入增长来源
SaaS 的收入增长常见来源包括：

+ 新增客户数提升
+ 客户续费率提升
+ 扩模块销售
+ 席位数增长
+ 提价
+ 渠道拓展
+ 从 SMB 向中大客户升级
+ 从单点工具向套件化平台升级

对成熟 SaaS 来说，长期更优质的增长通常来自：

> 存量客户扩单和高 NRR，而不是单纯堆新增。
>

# 六、成本模型
## 6.1 主要成本构成
+ 销售与获客成本
+ 渠道分成
+ 产品研发成本
+ 云基础设施与服务器成本
+ 客户成功与售后支持成本
+ 实施交付成本
+ 客服成本
+ 管理费用
+ 合规与安全成本

## 6.2 成本分类方式
### 固定成本
+ 研发人员工资
+ 管理人员工资
+ 核心平台与基础技术投入

### 可变成本
+ 云资源成本
+ 实施服务成本
+ 渠道佣金
+ 客户支持成本
+ 按客户数扩张的销售费用

### 前端成本
+ 市场投放
+ 销售团队
+ 渠道合作
+ 售前支持

### 后端成本
+ 研发
+ 实施
+ 客户成功
+ 运维和安全

## 6.3 单位经济模型
SaaS 最核心的单位经济模型通常是“单客户经济”：

```latex
单客户生命周期价值（LTV） = 生命周期收入 × 毛利率
```

```latex
CAC = 销售与营销成本 / 新增付费客户数
```

```latex
LTV/CAC = 单客户生命周期毛利贡献 / 获客成本
```

```latex
CAC回收周期 = 获客成本 / 单客户月毛利贡献
```

### SaaS 判断重点
+ 如果 CAC 回收周期过长，增长可能只是“烧钱换收入”
+ 如果续费率低，再高的新增也难形成复利
+ 如果服务交付过重，名义 SaaS 可能本质更像软件外包

## 6.4 利润公式
```latex
利润 = 收入 - 云成本 - 交付成本 - 销售与营销费用 - 研发费用 - 管理费用
```

# 八、行业经营逻辑
## 8.1 核心增长逻辑
SaaS 的增长本质有两条线：

### 线一：新增增长
+ 更多线索
+ 更高销售转化
+ 更强渠道拓展
+ 更多客户签约

### 线二：存量增长
+ 更高续费率
+ 更多席位扩张
+ 更多模块销售
+ 更强价格权

高质量 SaaS 更看重第二条线，因为：

> 存量扩张决定复利，新增只决定起量。
>

## 8.2 规模效应
规模扩大后，SaaS 可能出现以下优势：

+ 研发成本被更大客户基数摊薄
+ 品牌增强降低获客成本
+ 标准化模板提升实施效率
+ 客户案例增多，销售转化更容易
+ 生态合作增强，形成渠道和集成优势

## 8.3 网络效应
SaaS 通常没有特别强的经典双边网络效应，但可能存在：

+ 数据网络效应：更多客户数据使模型、报表、模板更优
+ 生态网络效应：更多集成伙伴提升平台价值
+ 组织嵌入效应：用得越深，切换成本越高

## 8.4 标准化与人力依赖程度
SaaS 最关键的判断之一是：

> 它到底是“真 SaaS”，还是“披着 SaaS 外衣的项目制服务”。
>

需重点看：

+ 是否可快速复制上线
+ 是否高度定制
+ 是否销售重、交付更重
+ 是否离开人工服务后客户无法使用

# 九、竞争格局与壁垒
## 9.1 竞争格局
SaaS 行业常见特点：

+ 细分赛道很多，整体高度分散
+ 水平 SaaS 更易出现头部平台
+ 垂直 SaaS 通常强依赖行业 know-how
+ 大厂可能通过流量、云、生态进入
+ 企业级客户市场往往竞争更长周期、更重交付

## 9.2 常见壁垒类型
+ 产品壁垒：功能深度、流程完整性、易用性
+ 数据壁垒：客户历史数据沉淀
+ 流程嵌入壁垒：系统进入核心业务流程
+ 生态壁垒：开放平台、插件、集成伙伴
+ 品牌与案例壁垒：大客户背书增强销售效率
+ 渠道壁垒：伙伴体系覆盖区域和行业
+ 客户切换成本：迁移成本、培训成本、重建流程成本

## 9.3 替代风险
+ 被 ERP、大平台、办公平台替代
+ 被上下游整合
+ 被低价同质化竞争拖入价格战
+ 被 AI 新工具重构交互方式和功能边界
+ 客户自研或继续用 Excel/低代码替代

# 十、行业风险分析
## 10.1 通用风险项
+ 获客成本过高
+ 续费率不足
+ 服务收入过重，导致毛利率低
+ 产品标准化不足
+ 客户决策周期过长
+ 大客户依赖
+ 与大厂竞争中被挤压
+ 数据合规与安全风险
+ 估值建立在收入增长而非经营质量上

## 10.2 风险信号模板
看到下列情况要警惕：

+ 收入增长快，但销售费用率长期居高不下
+ 续费率低，NRR 明显低于 100%
+ 实施收入占比过高
+ 前五大客户收入占比过高
+ 毛利率低于同类 SaaS 常见水平
+ 每签一个客户都要重新定制
+ 系统上线慢，客户成功依赖大量人工
+ 账面 ARR 增长但经营现金流没有改善

# 十一、财务分析重点
## 11.1 利润表重点
重点看：

+ 订阅收入和服务收入占比
+ 毛利率结构
+ 销售费用率
+ 研发费用率
+ 客户成功与实施成本
+ 是否接近经营杠杆释放点

## 11.2 资产负债表重点
重点看：

+ 现金储备
+ 合同负债 / 递延收入
+ 应收账款
+ 资本化研发
+ 有息负债
+ 商誉（如并购扩张）

## 11.3 现金流量表重点
重点看：

+ 经营现金流是否优于利润表表现
+ 回款周期是否健康
+ 预收模式是否稳定
+ 高增长是否伴随现金消耗失控

# 十二、市场空间分析模板
## 12.1 TAM / SAM / SOM
### TAM
企业数字化软件总体支出空间

### SAM
公司当前能力能服务的特定行业、特定客户类型的软件市场

### SOM
公司中短期可获得的实际市场份额

## 12.2 通用测算公式
### 方法一：企业客户法
```latex
市场空间 = 目标客户数 × 年均 ACV
```

### 方法二：席位法
```latex
市场空间 = 可服务企业员工数 × 席位渗透率 × 单席位价格
```

### 方法三：模块法
```latex
市场空间 = 企业数 × 模块渗透率 × 模块年费
```

## 12.3 市场空间判断注意事项
+ 不要把所有企业都当潜在客户
+ 要区分 SMB、中型客户和大客户
+ 要考虑本地化、行业化、实施能力的现实限制
+ 不同细分赛道市场空间差异很大，不能泛化

# 十四、快速分析卡
## 一句话本质
> SaaS 本质上是通过持续订阅嵌入客户业务流程，并依靠续费和扩单形成长期复利收入的行业。
>

## 核心收入公式
```latex
收入 = 客户数 × ACV
```

## 核心成本公式
```latex
成本 = 获客成本 + 实施交付成本 + 云资源成本 + 研发成本 + 客户成功成本
```

## 核心判断三要素
1. 续费是否强
2. 扩单是否自然
3. 标准化是否足够高

## 最重要指标
+ NRR
+ ACV
+ CAC 回收周期
+ 毛利率
+ 订阅收入占比

## 最大风险
+ 伪 SaaS，实则项目制
+ 高增长但单位经济不成立
+ 被大厂 / ERP / AI 工具替代

## 最终结论模板
> SaaS 行业的核心不是签了多少客户，而是客户是否真正把产品嵌入流程、是否持续续费并不断扩单。真正决定长期价值的不是短期收入增速，而是 NRR、标准化程度和单位经济质量。
>
