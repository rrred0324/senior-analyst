# 一、行业基础定义

## 1.1 行业名称
- 行业名称：金融科技
- 细分赛道：支付科技、信贷科技、财富科技、保险科技、风控科技、金融 SaaS、金融基础设施、嵌入式金融等
- 上下游位置：
  - 上游：银行、持牌机构、清算网络、征信与数据服务商、云与技术供应商、支付通道
  - 中游：金融科技平台、技术服务商、流量平台、风控平台
  - 下游：个人用户、小微商户、企业客户、金融机构
- 主要服务对象：To C、To B、To F（金融机构）

## 1.2 行业一句话定义
> 金融科技行业的本质是：用技术重构支付、融资、理财、保险和风控等金融服务流程，以更低成本、更高效率和更强可得性连接资金、资产、用户和金融机构，并通过手续费、利差分成、技术服务费和增值服务实现商业化。

## 1.3 行业边界

### 覆盖范围
- 与金融交易、支付、信贷、保险、理财相关的技术平台和服务
- 为金融机构或终端用户提供数字化金融基础设施的业务
- 通过技术提升金融效率、风控和用户体验的公司

### 不覆盖范围
- 传统纯金融机构本体业务
- 无科技属性的单纯金融中介
- 单纯 ERP/财务软件且无金融服务属性的业务
- 无支付、风控、资产或金融流程重构能力的泛流量平台

# 二、行业本质与核心价值

## 2.1 商业本质

金融科技的本质不是“做金融”，也不是“做软件”，而是：

> 用技术降低金融交易与风控成本，提高金融服务的覆盖效率、匹配效率和可管理性。

### 1）客户为什么需要它？
个人用户、小微商户或机构需要金融科技，通常是因为：
- 支付更便捷
- 融资更快
- 理财更低门槛
- 保险更易触达
- 风控更精准
- 合规流程更数字化
- 传统金融服务流程慢、成本高、覆盖不足

### 2）企业提供的核心价值是什么？
- 连接资金端和需求端
- 降低交易摩擦
- 提升审批、支付、结算、核保、理赔等效率
- 提供数字化风控
- 提升金融服务普惠性
- 帮助金融机构获客、运营和风控

### 3）企业为什么能赚钱？
金融科技公司的盈利来源通常来自：
- 支付手续费
- 技术服务费
- 流量导流费
- 利差分成
- 风控费
- 账户管理费
- 保险佣金或服务费
- 财富管理分销费
- SaaS/系统收费

## 2.2 价值创造链条

金融科技行业典型链路：

### 支付型
```text
获取商户/用户
→ 接入支付通道
→ 完成交易处理
→ 清结算
→ 数据沉淀
→ 增值服务（风控/营销/融资）
→ 收入确认
```

### 信贷科技型
```latex
获取借款需求
→ 身份识别与反欺诈
→ 风控建模
→ 匹配资金方
→ 放款
→ 贷后管理
→ 回收与分润
→ 数据迭代优化
```

### 财富/保险科技型
```latex
获取用户
→ 风险测评/需求识别
→ 产品推荐
→ 完成购买
→ 持有/理赔/复购
→ 分销或服务收入
```

## 2.3 行业核心飞轮
```latex
更多交易与用户
→ 更多数据沉淀
→ 更好的风控与推荐能力
→ 更高转化率和更低坏账/欺诈
→ 更强合作机构信任
→ 更多产品和资金接入
→ 更多交易与用户
```

金融科技真正强的飞轮是：

> 数据、风控、合规和渠道能力共同增强，形成交易效率和资产质量的双重复利。
>

# 四、商业模式分类
## 4.1 主要收入模式
### 模式一：手续费
+ 名称：Transaction Fee
+ 收费对象：商户/用户/机构
+ 收费方式：按交易额或笔数收费
+ 公式：

```latex
收入 = 交易规模 × 费率
```

### 模式二：导流与撮合费
+ 名称：Lead / Matching Fee
+ 收费对象：资金方/金融机构
+ 收费方式：按成功转化客户或放款规模收费
+ 公式：

```latex
收入 = 成功转化量 × 单位导流费
```

或

```latex
收入 = 放款规模 × 分润率
```

### 模式三：技术服务费
+ 名称：Technology Service Fee
+ 收费对象：银行、保险、券商、商户、平台
+ 收费方式：按系统部署、订阅、调用量、项目制收费
+ 公式：

```latex
收入 = 客户数 × 客均服务费
```

### 模式四：利差/分润
+ 名称：Spread / Revenue Sharing
+ 收费对象：金融合作机构
+ 收费方式：按资产收益、管理费或利差分成
+ 公式：

```latex
收入 = 资产规模 × 分润率
```

### 模式五：增值服务费
+ 名称：Value-added Service
+ 收费对象：商户/用户/机构
+ 收费方式：账户管理、营销、风控、数据、会员、SaaS
+ 公式：

```latex
收入 = 付费客户数 × 客均增值服务费
```

## 4.2 行业最优商业模式
金融科技中高质量模型通常具备：

+ 交易或资产规模可持续增长
+ 风控能力经得起周期考验
+ 合规清晰
+ 与持牌机构合作关系稳定
+ 多层变现能力
+ 不单纯依赖流量套利

理想模型不是：

> 靠一波流量做短期套利
>

而是：

> 在合规框架下沉淀交易、数据、风控和合作生态，形成长期金融基础设施能力。
>

## 4.3 从单点服务到综合变现路径
```latex
先做支付/导流/基础服务
→ 积累交易和用户数据
→ 提供风控/营销/运营增值
→ 接入更多金融产品
→ 构建平台化金融服务能力
```

# 五、收入模型
## 5.1 总收入公式
```latex
总收入 = 手续费收入 + 技术服务收入 + 导流撮合收入 + 利差/分润收入 + 增值服务收入 + 其他收入
```

## 5.2 拆解驱动因子
### 支付科技常见拆法
```latex
收入 = TPV × 综合费率
```

### 信贷科技常见拆法
```latex
收入 = 流量规模 × 转化率 × 客均放款额 × 变现率
```

或

```latex
收入 = 放款规模 × 技术/分润费率
```

### 财富科技常见拆法
```latex
收入 = AUM × 综合货币化率
```

### 保险科技常见拆法
```latex
收入 = 保费规模 × 佣金率
```

## 5.3 收入增长来源
+ 交易规模增长
+ 用户数和商户数增长
+ 通过率提升
+ 客均交易额提升
+ AUM 提升
+ 产品线扩充
+ 机构客户增加
+ 费率优化
+ 增值服务渗透率提升

# 六、成本模型
## 6.1 主要成本构成
+ 获客成本
+ 通道成本
+ 风控和反欺诈成本
+ 数据采购成本
+ 技术研发成本
+ 客服与运营成本
+ 坏账或风险分担成本
+ 合规与牌照相关成本
+ 资金合作和清结算成本
+ 管理费用

## 6.2 成本分类方式
### 固定成本
+ 技术平台研发
+ 合规与法务
+ 核心管理团队
+ 基础系统与安全投入

### 可变成本
+ 通道费
+ 数据调用费
+ 导流成本
+ 风险补偿
+ 客服成本
+ 分润成本

### 前端成本
+ 市场投放
+ 渠道佣金
+ BD 成本
+ 商户拓展成本

### 后端成本
+ 技术研发
+ 清结算
+ 风控运营
+ 贷后管理
+ 客服与合规

## 6.3 单位经济模型
### 支付型
```latex
单笔交易利润 = 单笔收入 - 通道成本 - 风控/技术成本 - 客服成本
```

### 信贷科技型
```latex
单客利润 = 单客变现收入 - 获客成本 - 风控成本 - 贷后成本 - 风险补偿成本
```

### 财富/保险科技型
```latex
单用户LTV = 生命周期内分销/服务收入 - 获客与服务成本
```

### 核心判断
+ 规模增长若伴随坏账恶化，增长质量很差
+ 高交易额若费率和通道成本没有优势，利润不一定厚
+ 合规成本虽不直接产生收入，但会决定业务可持续性

## 6.4 利润公式
```latex
利润 = 收入 - 通道/数据/分润成本 - 获客成本 - 风控和技术成本 - 合规成本 - 管理费用
```

# 八、行业经营逻辑
## 8.1 核心增长逻辑
金融科技增长通常来自：

+ 更多用户或商户
+ 更高交易频次或资产规模
+ 更高转化率
+ 更多合作金融产品
+ 更强风控降低损失
+ 更多增值服务渗透

## 8.2 规模效应
规模扩大后可能带来：

+ 更多数据样本，模型更优
+ 更强资金方与机构合作信任
+ 更强议价能力
+ 更低边际技术成本
+ 更高品牌认知和用户信任

## 8.3 网络效应
部分金融科技存在弱到中等网络效应：

+ 更多商户 → 更多支付场景 → 更多用户
+ 更多用户和交易 → 更多数据 → 更好风控和推荐
+ 更多机构合作 → 更多产品供给 → 更高转化

## 8.4 标准化与人力依赖程度
+ 支付和基础设施类标准化较高
+ 信贷和保险场景运营、催收、人工审核可能更重
+ To F 金融 SaaS 类更接近软件服务模型
+ 高人力导向业务往往规模化受限

# 九、竞争格局与壁垒
## 9.1 竞争格局
+ 支付领域通常头部集中
+ 信贷科技受监管和牌照环境影响大
+ 财富和保险科技既竞争流量，也竞争信任与产品供给
+ 风控科技更依赖模型效果与场景适配
+ 大平台、银行科技子公司、持牌机构可能深度参与竞争

## 9.2 常见壁垒类型
+ 合规壁垒
+ 数据壁垒
+ 风控模型壁垒
+ 交易规模壁垒
+ 机构合作壁垒
+ 商户网络壁垒
+ 系统稳定性和安全壁垒
+ 品牌与信任壁垒

## 9.3 替代风险
+ 被持牌机构自建替代
+ 被大平台流量入口挤压
+ 被通用支付/金融基础设施替代
+ 监管变化导致模式失效
+ 风控优势被数据或算法同质化削弱

# 十、行业风险分析
## 10.1 通用风险项
+ 强监管风险
+ 合规边界不清
+ 牌照依赖
+ 坏账和欺诈上升
+ 资金方合作不稳定
+ 通道成本上升
+ 流量成本上升
+ 大客户或大机构依赖
+ 技术系统故障
+ 声誉风险

## 10.2 风险信号模板
+ 交易量增长但坏账率同步恶化
+ 收入增长过度依赖某单一机构或渠道
+ 合规罚单频发
+ 通过率提升主要靠放松风控
+ 单用户利润下降但公司继续冲规模
+ 业务表述是科技，但收入本质来自高风险金融敞口

# 十二、市场空间分析模板
## 12.1 TAM / SAM / SOM
### TAM
相关金融交易、支付、融资、理财、保险等总市场规模

### SAM
公司可服务的人群、商户、机构与场景对应的市场空间

### SOM
公司现实可取得的交易份额、资产管理份额或机构覆盖率

## 12.2 通用测算公式
### 方法一：交易规模法
```latex
收入空间 = 行业交易规模 × 可实现费率
```

### 方法二：用户法
```latex
市场空间 = 潜在用户数 × 渗透率 × 客均金融服务收入
```

### 方法三：机构客户法
```latex
To F市场空间 = 可服务机构数 × 客均合同额
```

## 12.3 市场空间判断注意事项
+ 交易空间不等于可得收入空间
+ 金融科技的可得市场受监管和合作牌照强约束
+ 高增长赛道不一定有高利润率
+ 同样的 TPV / 放款额，其利润质量差异可能极大

# 十四、快速分析卡
## 一句话本质
> 金融科技本质上是用技术提升金融交易、风控和服务效率，并在合规前提下连接用户、资产、资金与机构的行业。
>

## 核心收入公式
```latex
收入 = 交易/资产规模 × 综合变现率
```

## 核心成本公式
```latex
成本 = 获客成本 + 通道/分润成本 + 风控与数据成本 + 技术成本 + 合规成本 + 风险成本
```

## 核心判断三要素
1. 合规是否清晰
2. 风控是否真实有效
3. 收入是否可持续且不靠短期套利

## 最重要指标
+ TPV / 放款额 / AUM / 保费规模
+ 综合费率
+ 坏账率 / 欺诈率
+ CAC
+ LTV
+ 商户/机构留存率

## 最大风险
+ 监管变化
+ 风控失效
+ 大机构依赖
+ 技术与合规事故
+ 短期规模冲动掩盖长期资产质量问题

## 最终结论模板
> 金融科技行业的核心不是把交易量做大，而是在合规框架下把交易、风控、资金合作和技术能力做深。真正决定长期价值的不是短期规模，而是资产质量、机构信任、技术壁垒和合规可持续性。
>
