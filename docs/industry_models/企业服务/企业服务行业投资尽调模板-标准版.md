# 三、业务理解

## 3.1 公司到底做什么
1. 公司提供的是标准软件、平台能力、行业解决方案还是实施服务？
2. 客户使用产品解决哪个高频问题？
3. 产品主要嵌入哪条核心工作流？
4. 客户是谁，谁是决策人，谁是日常使用者？
5. 公司更像软件公司、咨询实施公司，还是平台公司？

## 3.2 解决什么问题
1. 帮客户解决的是效率、成本、收入增长，还是合规和风控问题？
2. 客户不使用该产品的现有替代方案是什么？
3. 替换现有方案的驱动力是什么？
4. 客户 ROI 是否清晰，多久回本？

## 3.3 商业模式
1. 收入主要来自订阅、授权、实施还是 API 调用？
2. 是否有稳定续费？
3. 是否有 Seat 扩张、模块加购和上行销售？
4. 是否存在过重定制化依赖？

# 五、市场与行业尽调

## 5.1 市场空间
1. 这个赛道是大通用软件赛道，还是垂直细分赛道？
2. TAM 是否建立在真实 IT 支出和真实付费意愿上？
3. 客户预算由哪个部门支出？
4. 行业景气和数字化投入周期如何？

## 5.2 行业格局
1. 主要竞争对手是本土 SaaS、传统软件厂商、大厂还是开源替代？
2. 市场集中度如何？
3. 价格竞争激烈吗？
4. 客户更看重品牌、价格、功能、服务还是集成能力？

## 5.3 行业趋势
1. 云化和订阅化趋势是否明确？
2. AI 是否会放大公司优势还是削弱产品壁垒？
3. 政策和数据合规要求会不会推动采购？
4. 从点工具向平台化是否存在趋势？

# 九、财务尽调

## 9.1 收入质量
1. 收入里订阅、实施、一次性授权占比分别是多少？
2. ARR 与收入确认的匹配关系如何？
3. 是否存在大项目一次性确认拉高业绩？
4. 回款和签约质量是否一致？

## 9.2 利润质量
1. 订阅毛利率是否稳定提升？
2. 实施业务是否拖累整体利润？
3. AI / 云成本是否侵蚀毛利？
4. 规模扩大后销售效率是否改善？

## 9.3 现金流质量
1. 经营现金流是否健康？
2. 是否过度依赖预收款？
3. 应收账款是否快速增长？
4. 扩张是否以牺牲现金流为代价？

## 9.4 资产负债表风险
重点看：
- 应收账款
- 合同资产
- 递延收入
- 现金
- 资本化研发
- 有息负债

# 十、团队与组织尽调

## 10.1 核心团队
1. 创始团队是否兼具产品、技术、销售和行业经验？
2. 是否有服务大客户或复杂行业客户的经验？
3. 是否过度依赖创始人销售？
4. AI、数据和平台能力团队是否完整？

## 10.2 组织能力
1. 公司更强在产品、销售、交付还是客户成功？
2. 是否具备跨行业或跨区域复制能力？
3. 是否建立了可标准化实施的方法论？
4. 组织是否能承接更大规模客户？

## 10.3 激励机制
1. 销售激励是否鼓励低质量签单？
2. 交付激励是否兼顾满意度和效率？
3. 客户成功团队是否对续费和扩张负责？
4. 产品团队是否聚焦平台化而不是碎片化定制？

## 11.2 公司壁垒
1. 壁垒来自产品能力、数据沉淀、工作流嵌入，还是生态和渠道？
2. 是否已形成客户迁移成本？
3. 是否具备安全、合规或行业认证壁垒？
4. 是否具备集成生态和平台壁垒？

## 11.3 替代风险
1. 客户是否容易切换到更便宜产品？
2. 是否容易被大厂 bundling 替代？
3. 是否存在 AI 原生新产品颠覆风险？
4. 客户自研概率高不高？

# 十二、风险尽调

## 12.1 业务风险
- 产品同质化
- 获客成本高企
- 续费率下降
- 客户使用深度不足
- 大客户过度定制化
- 交付瓶颈

## 12.2 财务风险
- 订阅收入增长慢于销售费用增长
- 高实施占比拉低利润
- 云成本和模型成本失控
- 回款变慢
- 大客户坏账风险

## 12.3 合规与法律风险
- 数据安全与隐私风险
- 行业监管合规风险
- 软件知识产权风险
- 合同与收入确认风险
- 开源协议风险
- AI 输出合规风险
