# 五、收入模型
## 5.1 总收入公式
```latex
总收入 = 主收入A + 主收入B + 增值收入C + 其他收入D
```

## 5.2 拆解驱动因子
每个收入来源都要继续拆：

### 通用拆法一：用户规模驱动
```latex
收入 = 用户数 × 付费率 × ARPU / ARPPU
```

### 通用拆法二：交易规模驱动
```latex
收入 = GMV / TPV / 流水 × take rate
```

### 通用拆法三：企业客户驱动
```latex
收入 = 客户数 × ACV × 续费率
```

### 通用拆法四：广告驱动
```latex
收入 = 流量规模 × 广告加载率 × eCPM
```

### 通用拆法五：项目驱动
```latex
收入 = 项目数 × 平均合同额
```

## 5.3 收入增长来源
分析未来增长由哪些因素贡献：

+ 用户数增长
+ 使用频次提升
+ 客单价提升
+ 付费率提升
+ take rate 提升
+ 扩品类
+ 扩区域
+ 扩客群

# 十二、市场空间分析模板
## 12.1 TAM / SAM / SOM
### TAM
行业理论总市场规模

### SAM
公司当前产品能力可服务市场

### SOM
公司中短期可获得市场份额

## 12.2 通用测算公式
### 方法一：用户规模法
```latex
市场空间 = 潜在用户数 × 渗透率 × 年均ARPU
```

### 方法二：企业客户法
```latex
市场空间 = 目标客户数 × 年均 ACV
```

### 方法三：交易法
```latex
市场空间 = 行业交易总额 × 在线化率 × 平台渗透率 × take rate
```

### 方法四：支出法
```latex
市场空间 = 客户年度相关支出 × 产品渗透率 × 可得份额
```

## 12.3 市场空间判断注意事项
+ 不要只看大盘，不看可服务市场
+ 不要把全行业支出都当可得收入
+ 要区分 GMV、TPV 与公司收入
+ 要考虑监管和替代限制

# 一、写作目标

所有行业分析文件必须做到以下四点：

## 1.1 统一结构
不同赛道可以不同，但分析逻辑必须一致：
- 先定义行业
- 再讲商业本质
- 再拆收入成本
- 再看指标
- 再谈壁垒和风险
- 最后落到投资判断

## 1.2 统一口径
避免同一概念在不同文件中表达不一致，如：
- GMV、收入、流水混用
- 用户数、活跃用户、付费用户不区分
- 留存、复购、续费口径混乱
- 毛利率与净利率混淆

## 1.3 统一粒度
每份文件都要尽量回答同一层级的问题：
- 行业是什么
- 公司怎么赚钱
- 增长靠什么
- 成本卡在哪里
- 壁垒在哪里
- 风险在哪里

## 1.4 统一输出标准
任何文件都应支持三种使用场景：
- 快速阅读：能 3 分钟看懂本质
- 深度研究：能顺着结构继续补充
- 横向比较：能和其他行业或公司对齐

避免：

+ 标题过深（四级、五级标题太多）
+ 标题过碎，导致文档像 checklist 而不像分析框架

## 4.3 标题命名风格
使用“名词型标题”，尽量避免口语化标题。

### 推荐
+ 行业本质
+ 收入模型
+ 成本结构
+ 竞争格局
+ 风险分析

### 不推荐
+ 这个行业到底是怎么回事
+ 为什么它能赚钱
+ 我们应该怎么看它

---

# 五、写作风格规范
## 5.1 先结论，后展开
每个重要部分，优先给出一句核心判断，再展开说明。

### 推荐写法
> 该行业的核心不是规模本身，而是规模背后的单位经济是否成立。
>

然后再补：

+ 为什么
+ 如何判断
+ 看什么指标

## 5.2 句式要短，逻辑要硬
尽量写成投资判断语言，而不是宣传语言。

### 推荐
+ 行业增长快，但毛利率不稳定。
+ 该模式收入可见性强，但交付较重。
+ 核心壁垒来自供给控制，而非流量。

### 不推荐
+ 该公司拥有非常优秀且极具前瞻性的商业模式。
+ 该赛道未来发展潜力巨大，值得重点关注。

## 5.3 少空话，多变量
每一段尽量落到：

+ 变量
+ 机制
+ 指标
+ 风险

### 推荐表达
+ 增长主要取决于 CAC 是否低于 LTV。
+ 平台粘性取决于供需两端是否形成正循环。
+ 毛利率改善取决于标准化率和交付效率。

## 5.4 少“趋势判断”，多“结构判断”
趋势可以写，但必须落到结构：

+ 是什么结构导致增长
+ 是什么结构导致利润
+ 是什么结构导致壁垒
+ 是什么结构导致风险

# 六、定义与口径规范
## 6.1 收入相关口径
### 收入（Revenue）
公司确认到利润表的营业收入。

### GMV（Gross Merchandise Volume）
平台撮合成交总额，不等于公司收入。

### TPV（Total Payment Volume）
支付总交易额，不等于公司净收入。

### 流水
泛指交易额或充值额，必须明确是否等同 GMV / TPV / 总充值。

### take rate
```latex
take rate = 平台收入 / 平台撮合交易额
```

---

## 6.2 用户相关口径
### 注册用户
历史注册过的总用户。

### 活跃用户
在某一统计周期内有过活跃行为的用户。

### DAU / MAU
日活/月活，必须明确统计口径。

### 付费用户
统计周期内有过付费行为的用户。

### ARPU
```latex
ARPU = 某周期收入 / 总活跃用户数
```

### ARPPU
```latex
ARPPU = 某周期收入 / 付费用户数
```

---

## 6.3 B端客户口径
### 客户数
实际签约并贡献收入的企业数量，需区分：

+ 累计客户数
+ 当前活跃客户数
+ 付费客户数

### ACV
```latex
ACV = 单客户年合同金额
```

### NRR
```latex
NRR = 期初客户在本期续费+扩单收入 / 期初客户收入
```

### GRR
```latex
GRR = 期初客户续费收入 / 期初客户收入
```

---

## 6.4 留存与复购口径
### 留存率
某批用户在之后某周期仍活跃的比例。

### 复购率
购买后再次购买的用户比例。

### 续费率
订阅客户到期后继续付费的比例。

### 回流率
流失后再次活跃/购买的用户比例。

---

## 6.5 成本与利润口径
### 毛利率
```latex
毛利率 = （收入 - 主营业务成本）/ 收入
```

### 经营利润率
```latex
经营利润率 = 经营利润 / 收入
```

### CAC
```latex
CAC = 获客总成本 / 新增付费客户数
```

### LTV
```latex
LTV = 单客户生命周期总毛利贡献
```

### CAC 回收周期
```latex
CAC 回收周期 = 获客成本 / 月度毛利贡献
```

---

# 七、公式写法规范
## 7.1 所有公式单独成块
统一使用代码块，避免正文内混杂。

### 标准格式
```latex
收入 = 用户数 × 付费率 × ARPPU
```

## 7.2 公式从总到分
先给总公式，再拆因子。

### 示例
```latex
收入 = GMV × take rate
GMV = 购买用户数 × 购买频次 × 客单价
```

## 7.3 同一文件内变量命名保持一致
例如：

+ 不要同时写“客单价 / AOV / 平均订单金额”
+ 选一个主表达，其余首次出现时备注即可

# 八、指标体系写法规范
## 8.1 指标必须分层
不能把所有指标堆在一起，必须按层组织：

+ 规模指标
+ 增长指标
+ 转化指标
+ 留存/复购指标
+ 变现指标

+ 效率指标

+ 为什么看这个指标？
+ 指标高低说明什么？

### 推荐写法
+ 30日留存决定该产品是否具备稳定使用价值。
+ NRR 用于判断 B 端客户是否会自发扩张。
+ take rate 反映平台议价能力和变现深度。

## 8.3 每个行业保留“3-5个一级关键指标”
不要所有指标都当核心。必须明确真正重要的少数指标。

# 十、尽调文件写法规范
## 10.1 尽调不是行业介绍
尽调文件重点不是“行业多大”，而是：

+ 公司是不是真的解决问题
+ 数据是否成立
+ 增长是否可持续
+ 财务是否健康
+ 风险是否可控

## 10.2 尽调问题写法
每个问题尽量是“可验证”的，而不是泛泛发问。

### 推荐
+ 最近 12 个月客户续费率是多少？
+ 前 20 大客户收入占比是多少？
+ 若停止补贴，订单量预计下降多少？

### 不推荐
+ 你们的客户满意吗？
+ 你们未来怎么增长？
+ 你们有没有壁垒？

## 10.3 尽调结论必须分三类
+ 已验证成立
+ 尚需验证
+ 明确风险点

---

# 十一、对比文件写法规范
## 11.1 对比必须统一口径
不同公司比较时，必须尽量统一：

+ 时间周期
+ 指标定义
+ 收入确认方式
+ 是否含税
+ 是否合并口径

## 11.2 对比要分“事实”和“判断”
### 事实
+ 收入规模
+ 毛利率
+ 留存率
+ CAC
+ NRR

### 判断
+ 产品壁垒更强
+ 组织更成熟
+ 扩张能力更好

不能只写判断，不写事实支撑。

## 11.3 最后必须输出“谁更优，为什么”
不是简单列表，而是要得出结论：

+ 谁当前最强
+ 谁增长更快
+ 谁壁垒更深
+ 谁风险更大
+ 谁最值得投

---

# 十二、风险写法规范
## 12.1 风险必须具体
### 推荐
+ 收入增长依赖前三大客户，客户集中度过高。
+ 当前单城模型尚未盈利，扩张存在复制不成立风险。
+ 付费率提升来自强商业化，可能压制长期留存。

### 不推荐
+ 市场竞争激烈
+ 存在一定不确定性
+ 未来发展可能不及预期

## 12.2 风险最好对应预警指标
示例：

+ 风险：回款恶化  
+ 预警指标：DSO 连续两个季度上升
+ 风险：留存下滑  
+ 预警指标：30日留存连续 3 个月下跌

---

# 十三、结论写法规范
## 13.1 结论必须可投资使用
结论至少回答以下问题：

1. 这个行业/公司值不值得看？
2. 最重要的判断抓手是什么？
3. 最大风险是什么？
4. 下一步该验证什么？

## 13.2 推荐结论模板
### 商业建模结论
> 该行业本质上是一个________行业，核心价值来自________，长期胜负手不是________，而是________。
>

### 尽调结论
> 该公司当前最值得关注的点在于________，但要成立投资逻辑，仍需验证________；最大风险在于________。
>

### 对比结论
> 横向比较看，公司A 在________上领先，公司B 在________上更优，若以当前阶段投资优先级排序，建议________。
>

# 六、内容压缩与扩展规则

## 6.1 旧文件太长时怎么办
删减优先级：

### 优先删除
- 背景铺垫
- 重复概念解释
- 无指标支撑的宏观判断
- 和投资判断无关的行业历史

### 保留优先级高
- 收入逻辑
- 成本逻辑
- 留存/复购/续费
- 单位经济
- 竞争壁垒
- 风险信号

## 6.2 旧文件太短时怎么办
优先补充：
1. 行业本质
2. 核心公式
3. 关键指标
4. 单位经济
5. 风险项
6. 结论模板

# 七、行业差异化保留规则

统一模板不是抹平行业差异，而是统一骨架、保留变量。

## 7.1 哪些必须统一
- 结构顺序
- 指标分类方式
- 概念定义
- 结论格式
- 风险表达方式

## 7.2 哪些允许行业定制
- 核心收入公式
- 关键成本项
- 核心指标名称
- 供给侧结构
- 监管重点
- 投资判断抓手

### 示例
SaaS 看：
- ACV
- 续费率
- NRR
- CAC 回收周期

游戏看：
- 留存
- 付费率
- ARPPU
- LTV/CAC

本地生活看：
- GMV
- 订单密度
- 履约成本
- 单城模型

# 九、批量改造工作流建议

## 9.1 第一步：先分类
把所有旧文件先分为：
- 商业建模类
- 尽调类
- 对比类
- 一页纸类
- 其他辅助类

## 9.2 第二步：统一命名
把文件名改成：
```text
编号-行业名称-文件类型.md
```

## 9.3 第三步：统一结构
每类文件按对应母模板重排结构。

## 9.4 第四步：统一口径
替换不一致字段：

+ 流水 / GMV / 收入
+ 用户 / 活跃用户 / 付费用户
+ 留存 / 复购 / 续费

## 9.5 第五步：补齐缺失内容
补公式、指标、风险、结论。

## 9.6 第六步：增加可比性
每个行业文件最后尽量能提炼：

+ 该行业最关键的 3-5 个变量
+ 该行业最重要的投资判断问题
+ 该行业常见误区
